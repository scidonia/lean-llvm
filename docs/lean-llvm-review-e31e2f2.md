# lean-llvm review and captain’s plan

**20 November 2026 · Public main `e31e2f2` · Compared with the `f322b79` handoff and the subsequent review at `acccec1`.** [Reviewed commit](https://github.com/scidonia/lean-llvm/commit/e31e2f2c00bb572665f9cb9b140fcdd063df9997)

## Decision

Start two jobs now. Give one owner the writable Lake package cache and one owner the short tier-1 fraction proof. The infrastructure work makes sense for a fleet of proof workers, but the new wrapper deletes its own cache stamps. I reproduced the resulting loss of a warm build artifact. The fraction proof can proceed on an isolated worker while the build owner fixes that.

Since `f322b79`, the integer proof has a caller at function entry, and the fraction gate and exponent run have longer, reusable execution proofs. Since `acccec1`, the three new commits change five files covering Nix, Lake and documentation. No Lean source, parser implementation or benchmark transcript changed in that interval. The latest commits address worker provisioning. The evidence for semantic coverage and runtime speed is the same as at the last review. [Proof changes through acccec1](https://github.com/scidonia/lean-llvm/compare/f322b79...acccec1) · [Latest changes](https://github.com/scidonia/lean-llvm/compare/acccec1...e31e2f2)

## 1. Fix warm builds before sharing a cache

The flake now obtains Lean, mathlib and its dependencies from the pinned nixpkgs package set. It copies packages to a writable cache because Lake needs to write C objects when linking an executable. It also exports the Lake wrapper for machine images. Declaring `JsonMain` as a library gives the JSON test import a module build target. Both changes address concrete obstacles to bringing up a clean worker. The flake currently exports `x86_64-linux`. [Wrapper](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/flake.nix#L16) · [Test module target](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/lakefile.toml#L34)

**Confirmed defect.** The wrapper creates `$cache/stamps` and records each copied dependency there. Its pruning loop then visits every directory under `$cache` and retains only names in the dependency list. That list excludes `stamps`. On the next invocation, the missing stamp sends the package through `rm -rf` and a fresh copy. Generated objects in the writable tree disappear too. The `flock` serializes preparation, then releases before Lake builds. A second worker sharing that cache can therefore replace a tree the first is using. I reproduced the eviction sequentially. The concurrent interference is a consequence of the lock scope and was not exercised with live Lake processes. [Stamp, prune and lock scope](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/flake.nix#L42) · [Lake invocation](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/flake.nix#L102)

**Reproduction.** I ran the shell fragments from lines 42–47, 54–62 and 66–72 twice against a disposable store directory containing one package. The first call copied its source and removed the stamp directory. I placed a marker object inside the writable copy. The second call restored the source and removed the marker. This isolates the faulty operation without needing Nix.

**Repair and acceptance.** Keep metadata outside the directory enumerated for package pruning. Key overrides by dependency set and move stale-set collection out of the normal invocation path, so an older worktree remains usable during a rollout. On a real worker, build and link from a fresh cache, repeat through the wrapper, and check that the generated object survives and is reused. Then overlap two worktrees on one host and repeat with different lockfile revisions. Record first and warm elapsed time, whether copies or compilations ran, and successful exits. Until that passes, give each active worker its own `XDG_CACHE_HOME` to avoid cross-worker deletion. Isolation alone still permits the sequential recopy. Use the repository’s documented memory scope for each build. [Build commands and limits](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/AGENTS.md#L9)

## 2. Close one observable fraction result

The integer route gives the captain a working model of what to accept. Under its short-integer hypotheses, `intScan_t1_arm_at_entry` starts at the function’s real entry. On the fraction route, `fracScan_end230Cells` takes the staged dot-dispatch state to `if.end230`, preserving two integer cells. At that exit, `t1_fracEnd230_run` can already return success and write the eight bytes of `strtodSpec d`. To join the proofs, the latter also needs the sign, output pointer, two table pointers and the table contents at that **same** exit state. No new theorem closes that join in this revision. [Integer caller](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastCellsRun.lean#L213) · [Fraction producer](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastSeams.lean#L2941) · [Fraction consumer](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastGate.lean#L63)

1. **Freeze the endpoint.** State the theorem in a leaf module. Quantify over the staged input state, decimal model, sign, caller memory and tables. Keep the existing short-digit, no-exponent and tier-1 restrictions explicit. Conclude an actual `runFuel` return, success code, specified eight-byte write relative to the initial memory and the existing outside-region frame.
2. **Transport observations once.** Keep the dispatch and loop paths and their fuel equations paired with the same endpoint. Use the existing `BoundLoopPathFrame.toFrame` to transport the gate’s register observations. Verify memory preservation on dispatch and exit, expose the memory equality already carried inside `fracRunInv`, and use it to recover both table reads. The tier-3 peel is a worked example of deriving a caller’s register fact from a path. [Transport interface](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/LoopFuel.lean#L619) · [Peel instance](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastTier3Peel.lean#L511) · [Fraction invariant](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastDigitRuns.lean#L2740)
3. **Merge at the caller.** Require a compiling application with all register lookups and table reads for the existential exit discharged internally, and the repository’s axiom-footprint check. Afterward, ask a second worker to transport one additional preserved lookup through the exported path without editing its arms. That is a direct test of whether the next proof will be cheaper. Extending the theorem back to function entry is the following milestone.

The pipeline theorem still requires six walk-geometry suppliers. The fraction result advances one numeric case. To claim parser closure, identify the production consumer of that case and the remaining suppliers on the route to the parser contract. Keep them visible in the integration issue. [Pipeline theorem and supplier types](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/PipelineDischarge.lean#L2809)

## 3. Dispatch independent work through Git

| Work owner | File and interface ownership | Deliverable the captain can check |
|---|---|---|
| Build owner | Flake, package cache, wrapper smoke test and associated build instructions | Fresh link, warm reuse and overlapping-worktree checks above. Publish the tested lock revision for the other servers. |
| Fraction path owner | Fraction arms, dispatch and the scan endpoint in the existing digit-run and seam files | One endpoint preserving register facts, memory and fuel. Agree its signature with the caller owner before either edits. |
| Fraction caller owner | New leaf module against the agreed producer signature | Staged dot-to-return theorem. Stack this branch on the producer branch and merge in dependency order. |
| Performance owner | Benchmark harness and results only | Fresh-workspace versus reused-workspace runs on the same pinned core, inputs and compiler. Check equal verdicts and output contents before comparing times. |
| Captain | Umbrella imports, integration build and shared proof signatures | One owner per hot file, one branch per deliverable, SHA and build evidence in each handoff. Record elapsed time to the integrated theorem and files reopened for the extra lookup. |

Keep the exponent and heap work ready for spare capacity. An exponent worker can own a separate pure arithmetic module proving the digit recurrence on both sides of the saturation guard, targeting the `hacc` hypothesis of `expExit_merge`. A heap worker can use the actual stage-2 write frame to factor the repeated separation argument for the caller’s two count slots. Accept the heap change when both existing reads follow from the shared lemma with the same pipeline assumptions. Use the simpler memory equality for the read-only fraction scan. [Exponent consumer](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/JsonStage2NumFastSeams.lean#L3132) · [Two pipeline slot proofs](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/LeanLLVM/Refinement/PipelineDischarge.lean#L2443)

## 4. Make the next speed claim measurable

On the existing 64 KiB accepted synthetic inputs on CPU 0, the recorded native-route time divided by simdjson parse time is 1.68 for dense input, 5.98 for strings and 4.32 for UTF-8. End-to-end divided by simdjson padding plus parse ranges from 6.26 to 39.83 on those rows. These are historical harness timings with different output-consumption work. Run the workspace-reuse experiment on the unchanged kernel first. Report admission, staging, native call, copy-out and consumption separately, retain accepted and refused rows separately, and include a whole-call comparison for equivalent requested output. Use that result to decide whether another SIMD rewrite merits the proof cost. [Paired measurements and methodology](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/tests/json-units-bench/route-simdjson-transcript-paired.txt#L125) · [Existing optimisation proposal](https://github.com/scidonia/lean-llvm/blob/e31e2f2c00bb572665f9cb9b140fcdd063df9997/docs/speed-ratio-measures.md#L7)
